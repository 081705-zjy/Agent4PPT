# 从大模型推理优化到昇腾芯片的实践

## 整篇 deck 的论述弧线
背景挑战 → 通信重叠 → PD分离 → 实测效果 → 昇腾适配

## section 之间的逻辑关系
1. **封面** — 全 deck 的门面页，承载标题、讲者与机构；单页无内部弧线，为后续尺度定律切入与集群推理背景做身份铺垫。
2. **推理规模扩展的动机** — 承接封面，为后续 FlashOverlap 与 semi-PD 方案奠基：先立「尺度定律转向推理规模扩展」的大前提，再论证 Reasoning 模型引爆推理需求，最后补 LLM 推理基础概念，铺垫分布式集群推理挑战。
3. **分布式集群推理引擎与挑战** — 承接背景，系统铺陈分布式集群推理引擎全貌：由总览切入，依次拆解推理实例形态与并行策略两条技术主线，对标 SOTA 开源，末页收敛到现存挑战，为后续 FlashOverlap 与 semi-PD 方案埋下动机。
4. **FlashOverlap 计算通信重叠** — method 首章。先立「分布式推理通信开销不可忽略」这一痛点，再由 GEMM 与通信重叠思路收敛到 FlashOverlap 基于信号的重叠方案，末页给实测效果，为后续 semi-PD 铺路。
5. **semi-PD 融合与分离式实例方案** — 承接前文通信重叠方法，切入集群推理的实例编排问题；沿「挑战→背景→思路→方案」推进，以融合式与分离式实例对比为核心论证，收敛到 semi-PD 方案。
6. **实例与集群推理实测效果** — 承接前面 semi-PD 方案章节，用实测数据兑现前文承诺：先从单实例延时/吞吐切入，再到首 Token 延时，最后升级到实例与集群两级请求完成率对比，逐级放大验证方案有效性。
7. **昇腾芯片适配实践** — deck 收尾落地章节：把前文 FlashOverlap 与 semi-PD 方案迁移到昇腾芯片。先做昇腾 vs 英伟达软件栈对比，再逐层展开关键算子、重叠适配到弹性调度。
8. **结束页** — 全 deck 的收尾页，落在 semi-PD 方案与昇腾适配实践讲完之后，以讲者署名与单位结束整场，不承担新论点，仅作礼节性收束。
