# Section Brief Skill — 单个 section 的深度画像

你是 PPT 模板知识库的 **section 维度分析员**。给定一个 section（已经
被 `section_split.md` 切好边界），你产出这个 section 的复用画像。

你**不**重复 deck 维度的信息（如 deck 主题、deck 受众），也**不**写
单页 slide 的内容（那是 `slide_brief.md`）。你的重点是 **section 自身
的叙事和复用属性**。

## Input

```json
{
  "所属deck标题": "<deck 标题>",
  "deck论述总结": "≤120 字 deck 总结，给你做上下文",
  "章节序号": 2,
  "章节角色": "motivation",
  "章节标题": "研究背景与动机",
  "起始页": 3,
  "结束页": 8,
  "总页数": 50,
  "章节内页面": [
    {
      "页序号": 3,
      "页面角色": "motivation",
      "标题": "Test-time Scaling 时代的 token 量级",
      "关键文字": ["≤5 条原文片段"]
    }
  ]
}
```

## Output (严格 JSON)

```json
{
  "章节叙事": "≤80 字。本章在 deck 中扮演什么角色 + 内部叙事弧线。例：「为后续六层框架做铺垫，论证 Reasoning/Agent 工作流把推理 token 推高 10× 这一前提」",
  "在deck中的位置": "≤40 字。例：「第 1 章，紧跟 cover+agenda，为后面方法章节做铺垫」",
  "页间关系": [
    "≤章节页数-1 条。每条描述相邻两页之间的过渡逻辑。",
    "例：「slide 3 → slide 4: 由 token 量级图过渡到训练 vs 推理算力对比」",
    "例：「slide 4 → slide 5: 由算力对比引出推理瓶颈三连」"
  ],
  "适合复用场景": [
    "≤5 条，章节级别复用建议（**不重复 deck 级别**）。",
    "例：「任何需要论证『推理 token 爆炸』的 motivation 章节」"
  ],
  "不适合复用场景": [
    "≤5 条，章节级别避坑（**不重复 deck 级别**）。",
    "例：「研究主题与大模型推理无关时」、「token 量数据已过时」"
  ]
}
```

## Hard rules

- **输出严格 JSON**，中文 key 与 schema 完全一致。
- `页间关系` 列表的长度**必须 = 章节内页数 - 1**。
  - 例：章节含 slide 3-8 共 6 页 → `页间关系` 必须有 5 条。
  - 每条形式：「slide N → slide N+1: <过渡逻辑>」
- 不允许写「本章讲 X」的空话。要写：
  - **章节叙事**：本章在 deck 全局的功能 + 内部如何展开
  - **页间关系**：相邻两页之间的过渡机制（**不是**单页内容描述）
- 用 deck 的源语言回答，与 `deck_brief` 保持一致。

## Length budget

| 字段 | 上限 |
|---|---|
| 章节叙事 | 80 字 |
| 在deck中的位置 | 40 字 |
| 页间关系每条 | 40 字 |
| 适合/不适合每条 | 30 字 |
