# Generic Document Analysis Skill

分析项目 sources/ 下的纯文本类资料（.txt / .md / .docx / .rtf 等）。
PDF 走 `pdf_analysis.md`，PPTX 走 brief 4-skill 流水线。这个 skill 处理结构化程度
最低的纯文本文档。

## Input

```json
{
  "项目主题": "<brief.topic>",
  "项目主题标签": ["..."],
  "项目章节": [...],
  "文档": {
    "文件名": "research-notes.md",
    "格式": "md | txt | docx | rtf",
    "字数": 4200,
    "全文": "<完整文本>"
  }
}
```

## Output (严格 JSON, 中文 key)

```json
{
  "文件名": "research-notes.md",
  "资料类型": "research_notes | meeting_minutes | spec | tutorial | blog_post | 其他",
  "文档主题": "≤60 字",
  "核心论断": "≤100 字, 文档要传达什么 (断言式, 不是 '介绍 X' 这种描述式)",
  "结构概要": [
    "≤6 条, 每条 ≤60 字, 描述文档的章节/段落/主要论点骨架"
  ],
  "关键段落": [
    {
      "标题或位置": "## 第三节 / 第 5 段 / 开头部分",
      "原文摘录": "≤200 字原文, 不改写",
      "可引用场景": "≤40 字, 哪个章节可以引用"
    }
  ],
  "适合章节": [
    {"章节序号": 2, "章节名": "背景与动机", "为什么": "≤40 字"}
  ],
  "不适合章节": [
    {"章节序号": 5, "章节名": "代表性成果", "为什么": "≤40 字"}
  ],
  "主题标签": ["≤5 个原子词"],
  "relevance_score": 0.6,
  "discard_candidate": false
}
```

## 关键约束

- **`核心论断`** 必须是断言式:
  - ✅ "近一年大模型推理瓶颈从访存转向 KV 量化, 需重新规划方案优先级"
  - ❌ "本文讨论大模型推理"
- **`关键段落.原文摘录`** 是文档原文截取, 不要改写或翻译。
- **`结构概要`** 是骨架, 不是逐字摘要。每条概括一个主要部分.
- 当文档与项目主题严重不相关时, `relevance_score < 0.3`,
  `适合章节` 全空 → `discard_candidate=true`.
- 长文档 (>5000 字) 可以省略低价值段落, 但 `结构概要` 必须覆盖整篇.
- 短文档 (<500 字) 可以把全文当作单一关键段落.
- Output strict JSON only.

## Length budget

| 字段 | 上限 |
|---|---|
| 文档主题 | 60 字 |
| 核心论断 | 100 字 |
| 结构概要每条 | 60 字 |
| 关键段落.原文摘录 | 200 字 |
| 适合章节.为什么 | 40 字 |
